# Project 1: GitHub Actions - Test a Simple React App

Here is your study guide for Project 1. It covers the fundamental tools and commands you will use.

## Topic 1: Git Basics
Git is a version control system that runs locally on your machine. It tracks the history of changes to your code.
*   `git init` : Initializes a brand new, empty Git repository in your current folder. (We already did this!)
*   `git status` : Shows the current state of your files (which files are modified, which are ready to be committed).
*   `git add .` : Moves all your changed files to the "Staging Area" (getting them ready to be saved).
*   `git commit -m "Your message"` : Permanently saves the staged changes to your local repository history.

## Topic 2: Branching
Branches allow you to work on an experimental feature without breaking the `main` stable code.
*   `git branch <branch-name>` : Creates a new branch.
*   `git switch <branch-name>` : Switches your working directory to that branch.
*   `git checkout -b <branch-name>` : A shortcut that creates a new branch AND switches to it immediately.

## Topic 3: GitHub & Remote Repositories
GitHub is a website that hosts your Git repositories in the cloud so you can collaborate and run CI/CD.
*   `git remote add origin <github-url>` : Connects your local folder to a specific repository on GitHub.
*   `git push -u origin <branch-name>` : Uploads your local commits to the GitHub servers.
*   **Pull Request (PR)** : A feature on GitHub where you ask to merge your feature branch into the `main` branch. It allows your team to review the code before it is merged.

## Topic 4: GitHub Actions Basics
GitHub Actions is the CI/CD system built directly into GitHub. It reads `.yml` files in your repository and runs scripts on cloud servers.
*   **Workflow**: The entire automated process. It is defined by a `.yml` file placed inside the `.github/workflows/` folder.
*   **Events**: What triggers the workflow to start. Example: `on: push` (starts when someone pushes code).
*   **Jobs**: A group of tasks. By default, multiple jobs run at the exact same time (in parallel).
*   **Runners**: The actual virtual machine (usually an Ubuntu Linux server) that GitHub spins up to run your code.
*   **Steps**: The individual, sequential commands executed inside a Job (e.g., Step 1: checkout code, Step 2: run npm install).

### Example Workflow File (`.github/workflows/ci.yml`)
Below is the exact workflow we built for Project 1. It triggers on a push to `master`, spins up an Ubuntu server, downloads the code, installs Node.js, installs dependencies, and tests the React build.

```yaml
name: React CI Pipeline

on:
  push:
    branches: [ "master" ]

jobs:
  test-react-app:
    runs-on: ubuntu-latest

    steps:
      - name: 1. Download Code from GitHub
        uses: actions/checkout@v4

      - name: 2. Install Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: 3. Install React Dependencies
        run: npm install

      - name: 4. Check if the App Builds Successfully
        run: npm run build
```

### Detailed Breakdown: What Every Line Does

**The Trigger:**
*   `name: React CI Pipeline` : Gives your workflow a human-readable title that shows up on the GitHub Actions dashboard.
*   `on: push:` : Tells GitHub to "listen" for push events.
*   `branches: [ "master" ]` : Tells GitHub to *only* run this workflow when code is pushed specifically to the `master` branch.

**The Environment:**
*   `jobs:` : Starts the list of jobs. A workflow can have multiple jobs that run in parallel.
*   `test-react-app:` : The custom ID/name you are giving this specific job.
*   `runs-on: ubuntu-latest` : Instructs GitHub to rent a brand new, completely empty Ubuntu Linux virtual machine in the cloud just to run this job.

**The Steps (Executed in order on the Ubuntu machine):**
*   `steps:` : Starts the chronological list of tasks to execute.
*   `uses: actions/checkout@v4` : This is a "pre-built Action" made by GitHub. Because the Ubuntu server starts totally empty, this step downloads all of your repository's code onto that server so it can be tested.
*   `uses: actions/setup-node@v4` : Another pre-built Action. It installs Node.js onto the Ubuntu server.
*   `with: node-version: '20'` : Provides configuration to the step above, telling it exactly which version of Node to install.
*   `run: npm install` : Opens the terminal on the Ubuntu server and runs `npm install` to download your React app's dependencies (creating the `node_modules` folder).
*   `run: npm run build` : Runs the build script to ensure your React app compiles correctly without crashing. If this command fails, the entire GitHub Action fails (turns red)!

## Topic 5: Artifacts (Packaging the Build)
When GitHub Actions finishes running a job, it destroys the temporary Ubuntu server it was using. Anything you built (like the `dist/` folder containing your production-ready React app) is permanently deleted! 

An **Artifact** is a way to save files from your workflow so you can download them later from the GitHub website or pass them to another job (like a Deployment job). This covers the **"Package"** part of `Build -> Test -> Package -> Deploy`.

### Adding Artifacts to our Workflow
To save the `dist/` folder after our React app finishes building, we use another pre-built GitHub action called `actions/upload-artifact`. 

Here is what we add as **Step 5** in our workflow:

```yaml
      - name: 5. Save the Build (Artifact)
        uses: actions/upload-artifact@v4
        with:
          name: react-production-build
          path: dist/
```

### Detailed Breakdown:
*   `uses: actions/upload-artifact@v4`: Calls the official GitHub tool to compress and save files.
*   `with: name: react-production-build`: The custom name of the zip file that will be created and shown on your GitHub Actions dashboard.
*   `with: path: dist/`: Tells GitHub exactly which folder to save. Since `npm run build` creates a folder named `dist/`, that is the specific folder we want to preserve before the server is destroyed.
